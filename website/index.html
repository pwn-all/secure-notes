2. Description of Service

SecNote provides a zero-knowledge, end-to-end encrypted, one-time message relay hosted at [[HOST_URL]]/. Notes are encrypted client-side in your browser using AES-256-GCM before being transmitted. The decryption key exists only in the URL fragment (#) and is never sent to our servers. Notes are stored exclusively in server RAM and are permanently deleted after the first read or when the TTL expires. The Service is provided free of charge with no guarantee of uptime or availability.

Where the Operator enables it, a note may also carry file attachments up to a size limit set by the Operator. Attachments are packed together with the note text and encrypted in your browser in the same AES-256-GCM ciphertext, so the Operator sees only the total encrypted size; they are stored, deleted and expired exactly like text notes.

The Service additionally supports cross-instance retrieval: the frontend may be used to retrieve and decrypt notes whose encrypted ciphertext is stored on a third-party SecNote-compatible server (any server other than [[HOST]]). In such cases, your browser connects to that server to create or retrieve the note, and its availability, retention behavior, and configuration depend on that server's operator.

11. Zero-Knowledge Architecture

All notes are encrypted client-side with AES-256-GCM using the browser's native WebCrypto API before any data is sent to our servers. The encryption key is generated locally and exists only in the URL #fragment — browsers never include the fragment in HTTP requests, so the key is never transmitted to the server. The server stores only: an opaque note ID, the encrypted ciphertext, and a creation timestamp. We are technically incapable of reading note content.

12. Data We Collect

We are committed to minimal data collection:

  • No cookies. We do not set any cookies.
  • No accounts. No registration or personal information is required or collected.
  • No tracking. We do not use analytics services, advertising pixels, or fingerprinting.
  • Anti-spam hashing. For rate-limiting and spam prevention, a one-way SHA-256 hash of your IP address combined with a rotating server-side salt may be computed transiently in memory. This hash is never stored persistently, cannot be reversed to identify you, and is not shared with third parties.
  • Server logs. Standard server access logs (IP address, timestamp, HTTP method, response code) may be retained for up to 7 days for security and operational purposes, after which they are automatically deleted.
